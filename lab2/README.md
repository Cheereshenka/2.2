# Лабораторная 2 — Дерево задач

**Вариант 2. Система управления задачами с подзадачами.**

В лабораторной реализован паттерн проектирования **«Компоновщик» (Composite)**. Он позволяет представить проект как дерево, в котором отдельные задачи и группы задач обрабатываются через общий интерфейс.

## Оборудование и программная среда

Лабораторная подготовлена для компьютера, который используется в курсовом проекте:

- **Процессор:** Intel Core i7-12650H, 2,30 ГГц;
- **Оперативная память:** 16 ГБ;
- **Операционная система:** Windows 10;
- **JDK:** 17;
- **JavaFX:** 21.0.6;
- **Maven:** используется для сборки и запуска;
- **JUnit 5:** используется для автоматических тестов;
- **IntelliJ IDEA:** рекомендуемая среда разработки.

JavaFX 21 совместим с JDK 17, поэтому отдельная установка Java 21 для этой лабораторной не требуется.

## Что делает программа

После запуска открывается графическое приложение **«Дерево задач»**.

Программа предназначена для управления учебным проектом или набором работ. Задачи могут объединяться в проекты и подпроекты, поэтому структура имеет вид дерева:

```text
Учебный семестр
├── Лабораторные работы
│   ├── Изучить паттерны
│   └── Подготовить приложение
└── Оформить отчёт
```

У каждого элемента есть название. У простой задачи дополнительно хранятся:

- оценка времени в часах;
- срок выполнения;
- признак выполнения.

Для всего дерева автоматически рассчитываются:

- количество выполненных задач;
- общее количество задач;
- плановое время;
- фактически завершённое время;
- процент выполнения.

## Что происходит при запуске

Класс `Launcher` запускает JavaFX-приложение `App`.

В `App.start()` создаётся демонстрационное дерево:

1. создаётся корневой проект **«Учебный семестр»**;
2. в него добавляется группа **«Лабораторные работы»**;
3. в группу добавляются две простые задачи;
4. ещё одна задача добавляется непосредственно в корень;
5. одна из демонстрационных задач помечается как выполненная;
6. дерево отображается в `TreeView`.

После этого пользователь может выбрать любой элемент дерева и изменить его свойства.

## Как работает интерфейс

### Добавление подпроекта

Пользователь выбирает группу в дереве, вводит название и нажимает **«+ Подпроект»**.

Создаётся новый объект:

```java
TaskGroup child = new TaskGroup(name);
```

Затем он добавляется в выбранную группу:

```java
parent.add(child);
```

После изменения дерево перестраивается.

### Добавление задачи

Пользователь выбирает проект, указывает:

- название;
- количество часов;
- срок;
- статус выполнения.

После нажатия **«+ Задача»** создаётся `SimpleTask`.

### Редактирование

При выборе элемента его свойства загружаются в правую панель.

Для `SimpleTask` доступны:

- часы;
- срок;
- статус.

Кнопка **«Применить изменения»** изменяет выбранный объект.

### Завершение ветви

Кнопка **«Завершить всю ветвь»** вызывает:

```java
item.setDone(true);
```

Если выбран проект, `TaskGroup` передаёт эту операцию всем дочерним элементам рекурсивно.

Кнопка **«Вернуть ветвь в работу»** делает обратное:

```java
item.setDone(false);
```

### Удаление

Удаляется выбранный элемент вместе со всей его ветвью.

Корневой проект удалить нельзя.

## Что происходит внутри программы

Главная идея лабораторной — **единый интерфейс для листьев и контейнеров**.

Архитектура:

```text
                    TaskComponent
                         │
              ┌──────────┴──────────┐
              │                     │
         SimpleTask              TaskGroup
          (лист)                (контейнер)
              │                     │
       название                 список детей
       часы                     TaskComponent
       срок                          │
       статус               ┌────────┴────────┐
                            │                 │
                         SimpleTask       TaskGroup
```

### `TaskComponent`

Это абстрактный базовый компонент.

Он определяет общие операции:

- получение имени;
- переименование;
- получение родителя;
- расчёт общего времени;
- расчёт выполненного времени;
- подсчёт задач;
- получение прогресса;
- изменение статуса выполнения.

Благодаря этому `App` может работать с `TaskComponent`, не проверяя каждый раз, является ли выбранный элемент задачей или группой.

### `SimpleTask`

`SimpleTask` — **лист дерева**.

Он не содержит дочерних элементов.

Для него:

```text
getTotalTime()      → собственная оценка часов
getCompletedTime()  → часы, если задача выполнена
leafCount()         → 1
completedCount()    → 1 или 0
```

### `TaskGroup`

`TaskGroup` — **контейнер**.

Он содержит список:

```java
List<TaskComponent> children
```

Все расчёты выполняются рекурсивно.

Например:

```text
Учебный семестр
│
├── Лабораторные работы
│   ├── Задача А — 2 ч
│   └── Задача Б — 6 ч
│
└── Отчёт — 2 ч
```

Общее время:

```text
2 + 6 + 2 = 10 часов
```

Количество листовых задач:

```text
3
```

Если выполнена только задача А:

```text
1 / 3 = 33,3 %
```

Важно: прогресс считается **по количеству листовых задач**, а не как среднее процентов вложенных групп.

## Защита от ошибок в структуре

`TaskGroup` не позволяет:

- добавить `null`;
- добавить группу саму в себя;
- создать цикл в дереве;
- добавить компонент, который уже принадлежит другой группе.

Например, нельзя сделать:

```text
A → B → A
```

Такая структура привела бы к бесконечной рекурсии.

## Сохранение проекта

Класс `ProjectStore` отвечает за сохранение и загрузку дерева.

Проект сохраняется в обычный UTF-8-файл:

```text
project.properties
```

В файл записываются:

- название элемента;
- тип элемента;
- часы;
- срок;
- статус;
- количество дочерних элементов;
- структура дерева.

При загрузке дерево восстанавливается рекурсивно.

Использование обычного `properties`-файла удобно тем, что его можно открыть текстовым редактором и увидеть сохранённые данные.

## Что происходит при сохранении

Упрощённо:

```text
TaskGroup root
      │
      ▼
ProjectStore.save()
      │
      ▼
Properties
      │
      ▼
project.properties
```

При открытии происходит обратный процесс:

```text
project.properties
      │
      ▼
ProjectStore.load()
      │
      ▼
decode()
      │
      ▼
TaskGroup + SimpleTask
      │
      ▼
TreeView
```

## Тестирование

В проекте есть три основных модульных теста:

1. Проверка рекурсивного расчёта времени и прогресса.
2. Проверка запрета циклов и повторного использования одного компонента в разных группах.
3. Проверка сохранения и загрузки дерева с русскими названиями и выполненными задачами.

Также есть отдельная UI-проверка JavaFX.

Обычные тесты запускаются:

```powershell
.\mvnw.cmd test
```

UI-проверка:

```powershell
.\mvnw.cmd -Djavafx.smoke=true test
```

Она требует графической среды Windows.

## Что сказать преподавателю

**Краткое объяснение лабораторной:**

> В данной лабораторной реализована система управления иерархией задач. Основной паттерн — «Компоновщик». Он позволяет одинаково работать с простой задачей и группой задач через общий абстрактный класс `TaskComponent`. `SimpleTask` является листом дерева, а `TaskGroup` — контейнером, который хранит другие компоненты и рекурсивно выполняет над ними операции. Поэтому можно создавать проекты с несколькими уровнями вложенности, рассчитывать общее время и процент выполнения. Для сохранения используется UTF-8 properties-файл, а корректность основной логики проверяется JUnit-тестами.

## Итог

Лабораторная демонстрирует применение паттерна **Composite («Компоновщик»)** на практическом примере дерева учебных задач. Пользователь может создавать вложенные проекты и задачи, редактировать их, завершать целые ветви, отслеживать общий прогресс и сохранять результат в файл.

## Внешний вид

Интерфейс упрощён: убраны декоративные изображения и лишние визуальные элементы. Используется плоская цветовая схема с тёмно-бирюзовым заголовком, светлым фоном и минимальными рамками. Функциональные элементы приложения сохранены.
